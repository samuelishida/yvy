# Dashboard Enhancement — from static card wall to a useful public dashboard

## Context

`/dashboard` today is a flat grid of 9 self-fetching cards (`frontend/src/components/Dashboard.js:122-260`).
Each card fetches independently, hardcodes its own time window, formats numbers as
`toLocaleString('pt-BR')` regardless of locale, and has no filters, no drilldown, no
export, and no distinction between "loading" and "failed forever". Six of the nine
windows differ (24h / 7d / 30d / all-time / "~3 days") and none is stated as a
machine-readable timestamp — a reader cannot tell whether two numbers on the same
screen describe the same period. The page renders no `<h1>` at all.

There is also a large graveyard of intent: `Dashboard.css` ships unused `.stat-card*`,
`.sparkline-*`, `.dash-header`, `.spinner` blocks, and `i18n.js` ships ~40 unused
`dashboard.*` keys including `filterByBiome`, `filterRange`, `range7d/30d/90d`,
`wowVsPrev`, `clearFilters`. The previous design was planned and abandoned; this plan
finishes it.

**Intended outcome:** a general-public / press dashboard where every number is
scoped by one visible, URL-shareable filter (time range + region), framed against
the previous period so the reader knows whether it is good or bad, honest about
freshness and about data it does not have, clickable through to the map, and
exportable as CSV.

## Architectural decisions

- **Decision: one shared filter context, URL as the source of truth** (`?days=&state=`),
  read/written with `react-router-dom`'s `useSearchParams` (already a dependency,
  `frontend/package.json`). Rationale: press needs shareable links to a specific
  claim ("fires in Pará, last 30 days"); URL state also survives reload, which
  in-memory `apiCache` does not. Alternatives rejected: React state only (not
  shareable); `localStorage` persistence (a stale filter silently reframes every
  number on next visit).
- **Decision: a single `/api/dashboard/summary` route backs the KPI hero**, rather
  than the hero composing 5 existing endpoints client-side. Rationale: the hero must
  appear as one unit; 5 independent pop-ins is exactly the jank we are removing, and
  period-over-period deltas need two windows per metric — computing them server-side
  is one SQL pass instead of 10 round trips. Alternatives rejected: client-side
  composition (jank, 10 requests); GraphQL-ish generic aggregator (over-built for 6
  numbers).
- **Decision: biome becomes a persisted column on `fire_data`**, backfilled by a
  copas loop mirroring the existing `state_backfill_loop` (`backend-lua/app/init.lua:183-208`),
  instead of continuing to compute biome by point-in-polygon over a capped 10k-fire
  read (`biome_lookup.lua:119`, consumed by `/api/biomes`). Rationale: `/api/biomes`
  today cannot accept `days` or `state` at all because it never touches SQL
  aggregation — a filterable biome card is impossible without this. Alternatives
  rejected: widen the point-in-polygon cap (O(fires×polygons) on the single-threaded
  copas loop); precompute a static per-biome blob (kills the region filter).
- **Decision: `CardShell` owns loading / error / empty / freshness / export** for
  every card, so those four states are implemented once and cannot drift. Rationale:
  the current drift (only `HistoricalTrend` has an error branch; only DETER and CAR
  have empty states; `TIAtRisk` returns `null` on both empty and error) is a direct
  consequence of nine hand-rolled implementations.
- **Decision: no new frontend dependency.** CSV is generated by a ~30-line local
  util; PNG export serializes the recharts `<svg>` to a canvas. Rationale: CI's only
  frontend gate is `npm run build` (`.github/workflows/ci.yml:138-158`) and there is
  no frontend test harness at all, so every new dependency is unverified surface.
  Alternatives rejected: `html-to-image` / `file-saver` (needless for two small jobs).
- **Decision: keep hand-written CSS, prune dead blocks** (user-confirmed). Only rules
  this plan does not revive get deleted, in the final increment, after the revived
  ones are known.
- **Decision: DETER / AMS / CAR cards degrade honestly, no local ingest**
  (user-confirmed). `CardShell` gets an explicit `unavailable` state that names the
  upstream source and its last successful ingest, distinct from `empty` ("ingest ran,
  found nothing").

## Assumptions and answers from code

- Router has **no `:param` support** — exact-path match only; all variables go in the
  query string. Source: code @ `backend-lua/app/server.lua:67-75,271-272`, noted at
  `backend-lua/main.lua:207`. New routes are therefore `/api/dashboard/summary?days=&state=`.
- Handlers must open with `if not auth.enforce(ctx) then return end` then
  `if not rl.enforce(ctx) then return end`; omitting either leaves the route
  unauthenticated/unlimited. Source: code @ `backend-lua/app/routes/deforestation_stats.lua:64-65`.
  Newer route groups are registered lazily via a closure that `require`s inside.
  Source: code @ `backend-lua/main.lua:178-190,201-235`.
- Check command: **`make test-lua`** → `cd backend-lua && busted --verbose tests/*.lua`
  (`Makefile:24-25`), plus `luac -p` on every non-test Lua file and
  `CI=true DISABLE_ESLINT_PLUGIN=true npm run build` in `frontend/`. Source: code @
  `.github/workflows/ci.yml:51-61,138-158`. Lua **5.1** syntax only (no `goto`, no `//`).
  Busted needs a live Redis on 6379.
- **No frontend test harness exists** — no `test` script, no `@testing-library`, zero
  `*.test.js`. Source: code @ `frontend/package.json:18-22`. Frontend verification is
  therefore build + explicit manual browser steps; every increment below states them.
- `fire_data` holds **166,152 rows spanning 2026-04-23 → 2026-08-07** (~107 days), so
  a 90-day range is fully backed by data. Verified via `lsqlite3` query, 2026-08-08.
  `nature` is 100% classified (crime 43,987 / natural 51,287 / suspeito 70,878).
- **`deter_polygons`, `deter_alerts`, `deter_car_alerts`, `ams_risk` all have 0 rows**
  locally, and `lookup_data` holds only `biome_data`, `indigenous_lands`,
  `conservation_units` — **no `def_stats:*`**. Verified via `lsqlite3`, 2026-08-08.
  Consequence: `/api/deter/stats`, `/api/deter/car-alert-stats`, `/api/ams/*` and
  `/api/deforestation/stats/by-*` all return empty/`precomputed:false` in dev. Hence
  the `unavailable` state, and hence DETER cards are verified from seeded busted
  fixtures only.
- **67,283 fires (40.5%) have `state = ""`** — the sentinel the backfill writes when
  `classify_point` returns nil (`backend-lua/app/init.lua:196-199`). Re-running
  `state_lookup.classify_point` over a 3,000-row sample today recovers **2,055 (68%)**;
  945 are genuinely outside the IBGE polygons (offshore/coastal). Verified 2026-08-08.
  Consequence: a region filter is untrustworthy until repaired → **Inc 2 blocks Inc 7**.
- `db.count_fires_by_state_present()` (`db.lua:685`) and `db.count_unclassified()`
  (`db.lua:876`) already exist and are **unrouted** — the freshness panel consumes them
  rather than adding new SQL.
- `/api/fires/state-sparklines` has a latent bug: the row mapper reads `r.date` while
  the SQL selects `acq_date`, so every sparkline point's `date` is nil. Source: code @
  `backend-lua/app/db.lua:700-715`. Also `days` is unvalidated (`fires.lua:352`).
- Home already reads `?lat=&lng=&zoom=` and calls `map.setView` (code @
  `frontend/src/components/Home.js:402-409`); `TIAtRisk` is the only existing consumer
  (`makeMapUrl`, `TIAtRisk.js:7-17`). Layer visibility (`showFires`, `showDeforest`, …)
  is local state inside `MapaCard` (`Home.js:774-784`), so URL-driven layer selection
  requires lifting or seeding that state — scoped in Inc 9.
- `t()` returns the raw key path when unresolved (`i18n.js:470`), which is why
  `TIAtRisk.js:34,57` renders the literal strings "loading" / "fires" in both locales.
- `cachedFetch` is in-memory only, per-call TTL, with 429 backoff and in-flight dedup
  (`frontend/src/utils/apiCache.js:4-33`); `invalidateApiCache` exists at `:48-51` and
  is never called — Inc 1's retry button is its first consumer.
- Rate limit is 60 req/min/IP but **exempts private and loopback IPs entirely**
  (`app/middleware/rate_limit.lua:79-96`), so dev traffic through the C proxy is never
  limited; the dashboard's request budget must still be justified for public IPs.
- Redis caching is absent on all `/api/deter/*` and `/api/ams/*` — those hit SQLite
  directly on the single-threaded copas loop. New aggregate routes must cache.

## Risks accepted

- **The biome backfill rewrites all 166k `fire_data` rows' JSONB.** Mitigated by
  reusing the proven batched `state_backfill_loop` shape (500/batch, sleep between
  batches), writing only when biome is absent, and being additive — no reader depends
  on the new field until Inc 7. Accept the ~minutes of background churn.
- **Deltas can be misleading when the comparison window is partially ingested**
  (FIRMS lags, and 2026-08-03 is missing from the data entirely). Mitigated: the
  summary route returns `complete: false` on any window whose day-coverage is short,
  and the UI renders the delta as unavailable (`dashboard.wowUnavailable`, already in
  i18n) rather than a confident arrow.
- **Region filter can never reach 100% coverage** — ~31% of unattributed points are
  genuinely offshore. Mitigated: the freshness panel publishes the attribution
  coverage percentage, and filtered views label themselves as covering N% of points.
  Accept; revisit only if a higher-fidelity UF layer is adopted.
- **No automated test can catch a React regression here.** Mitigated: every frontend
  increment lists explicit manual browser steps, and all data-shaping logic that can
  live in Lua does, where busted covers it. Accept.
- **PNG export via SVG serialization will not capture CSS-drawn bars**, only recharts
  charts. Accept: CSV is offered on every card, PNG only where it is faithful.
- **DETER-dependent increments are verified only from fixtures.** Accept; the
  `unavailable` path is the one that will actually run in dev, and it is tested.
